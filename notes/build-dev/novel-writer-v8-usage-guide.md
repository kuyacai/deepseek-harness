# novel-writer v8 · 对话操作指引（给最终用户）

> **本文属于哪个插件**：**novel-writer v8**（包名 `@linfengqaqtat/dsh-scriptor`，本机实测 `0.1.0-preview.x`），即所谓的「网文写作工作台」。
> **不适用于** dsh-novel 插件（自研那套 `@dsh-novel/*`）。两者的用户说明**分开维护、互不引用**：dsh-novel 侧在 `dsh-novel-writer/docs/用户手册/`；本文只讲 v8。

本文写给**使用者**（作者），只回答一件事：**每一步该对模型说什么，才算"按流程走"而不是自由发挥。**
不解释插件内部机制（那部分见 `plugin-mechanism.md`），也不复述作品取值——具体设定一律以你的书仓文件为准。

配套阅读：`webnovel-writer-8/docs/user/workflows.md`（官方用户文档，讲"有哪些日常操作"）。本文只补充它没模板化的部分：**可照抄的起手句 + 锚点 + 验收 + 红线**。

---

## 1. 为什么需要这份文档

v8 的 10 个技能全部是 `user-invocable: false`——**你不能用斜杠点名技能**，只能靠自然语言触发。模型选不选得中技能、会不会跳过闸门，取决于你这句里有没有「锚点」。

所以「自由发挥」的代价不是"模型不听话"，而是**它按另一个节点走了**：前置工件没备、细纲没确认、定稿被当成草稿改。这份文档的作用就是把「该说什么」固化成模板，降低偏移概率。

> 注意：措辞**不必逐字照抄**，官方自己也只用自然语言示例。真正要保住的是**语义锚点**（见 §5），不是句子本身。

## 2. 三条总则

### 2.1 先校准进度

开场（以及断更、换会话、切书之后）第一件事是**核对事实，不是接着聊**。
照说：「先核对进度」——模型会调 `novel_get_story_status` 读事实清单，再谈下一步。

- 严禁让模型凭聊天记忆或上下文印象抢跑；
- 校准结果是「事实 + 建议」，建议仅供参考，当前该做什么由它判断；
- 你自己也别用记忆替它判断——**判断进度一律回文件**。

### 2.2 按节点走（重点说明）

**「按节点走」= 按 v8 生产线的既定节点顺序推进，一次只做当前节点的事；节点由状态校准决定，不由对话印象决定，也不由谁临时点菜。**

v8 有两条面的节点序列：

- **设计面**：灵感 → 定调(契约) → 世界构建 → 故事骨架 → 分卷布局 → 当前卷规划 → 开写就绪
- **章节面**：章细纲(待定位) → 章细纲(待确认) → 写作备料 → 写稿 → 润色 → 审核 → 改稿 → 定稿准备 → 作者裁决 → 定稿入档 → 完成

「按节点走」具体意味着四件事：

1. **节点由校准定，不由你指定起点。** 你能做的是「给目标 + 让它先核对」，而不是「跳过核对直接跳到某步」。例如说"继续第 2 章，先核对进度"，而不是"直接写第 2 章正文"。
2. **一步只推进一个节点。** 每一步的产物是下一步的输入：**没确认的细纲不许开写正文**，没备料的正文不算启动，没审读的稿子不能进定稿。催促跨步 = 让模型在缺前置的状态下硬走。
3. **默认不许跳节点。** 只有两种情况例外：① 你**明示**跳步（模型播报后照做，不自行绕过也不拒绝）；② 节点被「前置工件缺失」阻塞时，由你决定是否照常推进。
4. **你在这个结构里只有两个正当动作**：给**目标**（"继续第 N 章"）、给**裁决**（定稿入档 / 吃书补偿 / 创作决定）。其余环节是机械推进——完成一步后模型直接做下一步，**不需要你逐句发「继续」**（前提是：细纲已确认、你已委托本章）。

一句话：**节点是轨道，锚点是你扳的道岔。** 少了锚点，轨道就会并到别处。

### 2.3 到位即停

到以下位置**必须停下等作者**，模型不得自行往下走：

- 新的创作选择（走向 / 重要口径 / 细纲修订）；
- 影响的裁决（定稿入档、吃书补偿）；
- 工具故障、语义冲突、保真风险；
- 本章入档后——**不自动开下一章**，汇报近况即停。

## 3. 标准起手句模板

照这个说，比"帮我写小说"有效得多。

| 场景 | 照着说 | 期望动作 | 别这么说 |
| --- | --- | --- | --- |
| 继续某章 | 「继续《书名》第 2 章，先核对进度」 | 校准 → 判定当前节点 → 备细纲/写稿/审读/定稿 | 「直接写第 2 章正文」 |
| 开新书 | 「开一本新书，题材是修仙，先帮我收敛灵感、立项」 | 《灵感与立项》七要素 → 你确认 → 建书 | 「给我写一本修仙小说」 |
| 作品定调 | 「按快速路径起草契约，给我一次确认」 | 《定调设计》路径 A | 「设定你全定了，别问我」 |
| 卷规划 | 「准备第 2 卷卷纲，给我多方向候选」 | 多方向呈报 → 你选 → 落卷纲 | 「直接定第 2 卷大纲」 |
| 开写前 | 「先给我第 N 章细纲候选，我确认后再开写」 | 细纲 → **你要确认（闸门）** | 「不用细纲，直接写」 |
| 起草到改稿 | 「按流程走：起草 → 润色 → 审读 → 改稿，重大处置再报」 | 机械接续，逐步播报进展 | 「每一步都停下来等我发继续」 |
| 定稿 | 「这章我批准定稿」 | 裁决点 → 沉淀入档 | 「你自己看着定稿」 |
| 改设定/正文 | 「我改了世界书 X，帮我核对影响」 | 影响分析 → 提案 → 你裁决 | 「顺手把后面的章节也改了」 |
| 中断恢复 | 「我上次中断了，先核对文件与 git 状态再继续」 | 回读现状 → 接着对应节点 | 「重发一遍原来的指令」 |
| 暂停 | 「先暂停这一章」 | 记录停点 | （不说，让它自己飘） |
| 卷末 | 「第 1 卷收尾，核对计划章节 / 定稿 / 未回收事项」 | 卷摘要候选 → 你核对 | 「第 1 卷完了，开第 2 卷」 |
| 导出 | 「导出《书名》第 1 卷到 <目录>，含来源清单」 | 查冲突 → 写出 | 「导出发我」 |

## 4. 节点对照总表

### 4.1 设计面

| 节点 | 你说什么 | 前置 | 产出 | 你要验收什么 |
| --- | --- | --- | --- | --- |
| 灵感阶段 | 「帮我收敛这本书的灵感」 | 无 | 七要素 + 立项建议 | 题材/主角/卖点是否你认 |
| 作品定调 | 「起草契约 / 逐部细聊契约」 | 已建书 | 契约（路径 A 或 B） | 世界观口径、金手指维度 |
| 世界构建 | 「补人物档案与世界规则」 | 契约 | 世界书条目 | 设定是否自洽 |
| 故事骨架 | 「把骨架定下来」 | 契约 | 九部骨架 | 三线对位 |
| 分卷布局 | 「排一下分卷」 | 骨架 | 八部分卷 | 卷数与成长段分布 |
| 当前卷规划 | 「准备本卷卷纲」 | 分卷 | 卷纲 + 滚窗 | 本卷区间与节拍 |
| 开写就绪 | 「开始写第 1 章」 | 卷纲 | 进入章节面 | — |

### 4.2 章节面

| 节点 | 你说什么 | 前置 | 产出 | 你要验收什么 |
| --- | --- | --- | --- | --- |
| 章细纲(待定位) | 「准备第 N 章细纲」 | 卷纲 | 细纲候选 | 节拍是否对上卷纲 |
| 章细纲(待确认) | 「细纲我看了，确认」 | 细纲候选 | **闸门解除** | 你确认过才放行 |
| 写作备料 | 「备料」 | 细纲已确认 | 材料包 | 缺段如实播报 |
| 写稿 | 「按细纲起草」 | 备料 | 章节草稿 | 草稿落点 |
| 润色 | 「润色」 | 草稿 | 精修稿 | 表达清理 |
| 审核 | 「审读」 | 润色稿 | 五字段问题清单 | 发现项是否属实 |
| 改稿 | 「按处置改稿」 | 审读发现项 | 整改稿 | 处置是否落地 |
| 定稿准备 | 「准备定稿包」 | 改稿稿 | 包 + 裁决项 | 无未决项 |
| 作者裁决 | 「批准定稿」 | 定稿包 | 裁决记录 | **裁决点①** |
| 定稿入档 | （由裁决触发） | 批准 | `定稿/卷NN/NNNN-<标题>.md` | 入档 + 提交 |
| 完成 | 「汇报近况」 | 入档 | 近况 + 下一章规划 | — |

> 吃书补偿（改动已定稿事实）是**裁决点②**，走提案 → 影响分析 → 裁决 → `retcon:` 提交，不在上表常规轨道里。

### 4.3 典型场景使用参考

> 下面按**一个作者从零写完一本书的时间线**排序。每条是一份「用例」：先说此刻想干什么，再说该怎么说、会怎样、什么时候轮到你拍板。
> 本节只讲「怎么用」；节点定义仍见 4.1 / 4.2，避免两处漂移。

#### U1 构思一本书：从点子到立项

- **我想做什么**：手上有个点子，想知道它撑不撑得起一部长篇。
- **需要已有什么**：无——这是起点。
- **照这么说**：「开一本新书，题材是修仙，先帮我收敛灵感、立项」
- **会发生什么**：模型先做状态校准 → 加载《灵感与立项》→ 把点子收敛成七要素 → 呈报立项建议。
- **轮到你**：确认七要素（题材 / 主角 / 卖点 / 冲突 / 世界基调 / 篇幅 / 成长线）；你点头后才建书。
- **别这么做**：「给我写一本修仙小说」——跳过立项，模型会直接开写正文，后面全乱。

#### U2 写故事背景 / 定世界观

- **我想做什么**：把这本书的世界规则、力量体系、地理势力定下来。
- **需要已有什么**：已建书（U1）。
- **照这么说**：「起草契约，给我一次确认」（快路径）；或「逐部细聊契约」（慢路径）；或「补世界规则」
- **会发生什么**：加载《定调设计》。快路径一次起草找你确认；慢路径逐部聊并逐条确认世界书条目。
- **轮到你**：世界观口径由你定——模型只呈报与执行，不替你拍板。
- **别这么做**：「设定你全定了，别问我」——世界口径是作品核心，外包出去后面一定返工。

#### U3 定人物与关系

- **我想做什么**：主角、配角、关系网立住。
- **需要已有什么**：契约 / 世界基调已定（U2）。
- **照这么说**：「补人物档案和人物关系」
- **会发生什么**：模型按《定调设计》补人物条目（动机、弧光、关系线），写入世界书。
- **轮到你**：人物动机与关系线是否符合你的构想——**人物决定情节**，这里值得花时间。
- **别这么做**：人物没定就写正文 → 写着写着人物行为飘，只能回头改。

#### U4 定全书骨架与分卷

- **我想做什么**：把整本书的走向和卷数定下来。
- **需要已有什么**：契约 + 人物（U2 / U3）。
- **照这么说**：「把故事骨架定下来」→ 再「排一下分卷」
- **会发生什么**：九部骨架（三线对位）→ 八部分卷（卷 ↔ 成长段）。
- **轮到你**：确认骨架与分卷——此后卷纲都以它为上位。
- **别这么做**：骨架没定就排本卷大纲 → 卷纲无根。

#### U5 排本卷大纲

- **我想做什么**：把第 1 卷（或当前卷）细化到能开写。
- **需要已有什么**：分卷已定（U4）。
- **照这么说**：「准备第 1 卷卷纲，给我多方向候选」
- **会发生什么**：本卷首次落卷纲前，模型先出**多方向候选**供你选 → 落卷纲 → 滚窗。
- **轮到你**：选方向、确认卷纲。
- **别这么做**：「直接定第 1 卷大纲」——跳过候选，你就失去了选走向的机会。

#### U6 写某一章（核心循环）

- **我想做什么**：把第 N 章写出来。
- **需要已有什么**：本卷卷纲已定（U5）。
- **照这么说**：先说「给第 N 章细纲候选，我确认后再开写」；确认后说「按流程走：起草 → 润色 → 审读 → 改稿，重大处置再报」
- **会发生什么**：细纲 → **你确认（闸门）** → 备料 → 起草 → 润色 → 审读 → 改稿 → 备定稿包。中间机械步骤完成一步即走，不必你逐句催。
- **轮到你**：① 细纲确认（不开这个闸门不许写正文）；② 审读发现项的重大处置。
- **别这么做**：跳过细纲确认直接说「写第 N 章正文」；或者每完成一步都停下来等你发「继续」。

#### U7 对某一步不满意，要重做

- **我想做什么**：起草 / 润色 / 改稿的某一版不合意，想重来。
- **需要已有什么**：该步已有产物。
- **照这么说**：「第 N 章润色这版不行，重做」＋**说清退回哪个节点、不满意在哪**
- **会发生什么**：回到对应节点，单点重试或回滚——不推倒整章重来。
- **轮到你**：把「哪里不对」说清楚；这是创作决定，模型不替你判断。
- **别这么做**：只说「重来」——它不知道退回哪一步，可能整章重写，把好的部分一起冲掉。

#### U8 改了设定，要核对影响

- **我想做什么**：我改了世界书 / 大纲 / 契约里的东西，想知道牵动到哪些章节。
- **需要已有什么**：已定的真源文件。
- **照这么说**：「我改了世界书 X，帮我核对影响」
- **会发生什么**：影响分析（只算不写）→ 提案登记 → 呈报未定稿下游与已定稿命中 → 你裁决 → 未定稿下游整批整改；命中已定稿则走**吃书补偿**。
- **轮到你**：裁决——提案通过 / 驳回；吃书是**裁决点②**，必须你批。
- **别这么做**：「顺手把后面的章节一起改了」——绕过影响分析与裁决。

#### U9 中断后恢复 / 暂停

- **我想做什么**：先停一下；或上次断了，想接着写。
- **需要已有什么**：无。
- **照这么说**：暂停「先暂停这一章」；恢复「上次中断了，先核对文件与 git 状态再继续」
- **会发生什么**：暂停记录停点；恢复时回读现状、落回对应节点，已完成部分可继续用。
- **轮到你**：确认从哪继续。
- **别这么做**：重发原始 prompt（会被当成新一轮业务重跑）；暂停期间在别处手改同一章文件（会造成冲突）。

#### U10 卷末收尾与定稿

- **我想做什么**：这一卷写完了，收尾并把章节定稿。
- **需要已有什么**：本卷各章已过审。
- **照这么说**：卷末「第 1 卷收尾，核对计划章节 / 定稿 / 未回收事项」；定稿「这章我批准定稿」
- **会发生什么**：卷末出卷摘要候选；定稿走 备包 → 你裁决 → 沉淀入档（`ch:` 提交）。
- **轮到你**：**裁决点①——定稿入档必须你批**；卷摘要候选由你核对。
- **别这么做**：「你自己看着定稿」——定稿即正典、只读，事后要改只能走吃书补偿。

#### U11 导出

- **我想做什么**：把成书导出去。
- **需要已有什么**：有定稿章节。
- **照这么说**：「导出《书名》第 1 卷到 <目标目录>，含来源清单」
- **会发生什么**：先查冲突再写出；结果可重复核对；不会把草稿混进定稿。
- **轮到你**：平台排版与发布仍由你审——插件不代你投稿。
- **别这么做**：「导出发我」——不说范围，导出结果不可控。

## 5. 三个必留锚点

丢掉这三个词，含义就散了。

| 锚点 | 作用 | 丢了会怎样 |
| --- | --- | --- |
| **先核对进度** | 强制先读事实，再决定节点 | 模型凭上下文印象抢跑，落错节点 |
| **细纲确认** | 写稿前的前置闸门 | 会在细纲未定稿时直接起草，浪费一轮 |
| **审读修改 / 处置** | 审读发现项由你裁决，不能自动全收 | 发现项被"顺手全改"，偏离你的口径 |

> 原则：**不是让用户说的话跟官方一致，而是让同一批锚点触发同一批动作。**

## 6. 常见偏航与纠正

| 症状 | 原因 | 纠正 |
| --- | --- | --- |
| 跳过细纲直接写正文 | 起手句缺「细纲确认」锚点 | 补说「先给细纲候选，我确认后开写」 |
| 重发原始 prompt 后流程重跑 | 重复注入被当成新一轮业务 | 用「先核对进度」+ 明确目标，不重发原话 |
| 模型说"完成"但没记录 | 模型的口头"完成"≠审核记录/提交结果 | 要求出示审核记录与实际提交状态 |
| 保存 / 提交 / 理解混为一谈 | 三件事被当一件 | 「保存」「提交」「已交给主控」分开确认 |
| 中途在别处手改同一章 → 冲突 | 暂停期间改动同一章文件 | 暂停后先核对文件与 git，再继续 |
| 自动开下一章 | 跨章不自动滚窗 | 本章入档即停，下一章是新委托 |

## 7. 红线（不要授权模型做的事）

- **定稿只读**：`定稿/` 是正典，改动走吃书补偿，不能直接覆盖；
- **裁决点只有两处**：定稿入档、吃书补偿。其余写入，你明确要求的那一次即等于批准；
- **不代写、不替你拍板**：正文与创作决定由你（或你授权的子代理）定，模型不得自行编造规划、伪造审查结论；
- **跳步要先问**：前置缺失时它必须如实播报缺什么并请你决定，不得自行绕过；
- **切书要你明说**：跨书不自动切换写作目标。
